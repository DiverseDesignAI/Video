# YUVIO V9 — Final Interaction & Transition Fixes

## Основная задача

Исправить технические и визуальные ошибки в `yuvio-walkthrough-v8-10bit.mp4`.

**Не выполнять редизайн и не перестраивать видеоролик заново.**

Сохранить существующую композицию, анимацию, тексты, продолжительность, корпус iPhone, фирменную палитру и звуковое сопровождение.

Основной приоритет — устранение чёрных артефактов в Bottom Navigation.

---

## 01. Critical Fix — Bottom Navigation

В текущей версии при переключении вкладок внутри фиолетовых активных кнопок появляются чёрные элементы.

Обязательные участки проверки:

- `39.20–39.50` — Home → Card.
- `51.70–52.00` — Card → Activity.
- `57.30–57.70` — Activity → Profile.

### Проблема

При смене активной вкладки иконка на несколько кадров становится чёрной либо перекрывается чёрным кругом.

Это нарушает визуальную систему YUVIO и выглядит как ошибка отрисовки.

### Необходимо

Проверить:

1. Слои активного индикатора Bottom Navigation.
2. SVG-иконки и способ управления их цветом.
3. Наложения Pressed / Selected.
4. Дополнительные ripple или touch-feedback слои.
5. Z-index элементов.
6. Прозрачность и анимацию старой и новой активных вкладок.
7. Отсутствие дублирующихся экземпляров навигации.

Если для нажатия используется дополнительный чёрный круг, прямоугольник или radial overlay, удалить эту реализацию.

### Правильное поведение

При переключении вкладки:

- Новая вкладка получает фирменный градиент.
- Иконка активной вкладки остаётся светлой и читаемой.
- Текст сохраняет контраст.
- Старая вкладка возвращается к неактивному состоянию.
- Не появляются промежуточные чёрные круги, квадраты или маски.

Использовать настоящую визуальную систему YUVIO.

### Фирменный градиент

Linear:

- `0% — #AE9FFF`
- `42% — #806FE9`
- `82% — #6150CE`
- `100% — #45369A`

Направление градиента должно соответствовать UI Kit.

**Важно:** не применять этот градиент ко всем элементам без разбора. Использовать его только там, где соответствующее активное состояние предусмотрено исходным дизайном.

### Требование к реализации

Анимировать изменение состояния существующего компонента, а не создавать второй компонент поверх первого.

В любой момент времени для одной позиции навбара должен быть один корректный визуальный результат.

Использовать стабильные ключи элементов и единый источник состояния текущей вкладки.

Не допускать промежуточных кадров, в которых активная подложка уже появилась, а цвет иконки ещё не обновился.

## 02. Исправить переходы между экранами

Проверить участки:

- `25.70–26.00` — Receive → Home.
- `38.20–38.50` — View Receipt → Home.
- `53.30–53.60` — Activity → Transaction Details.

### Проблема

Во время некоторых переходов между экранами возникает слишком заметная граница между старым и новым интерфейсами.

Отдельные переходы выглядят как механическое перемещение двух прямоугольных изображений.

### Исправить

- Сохранить естественное направление iOS push/pop transitions.
- Убедиться, что оба экрана находятся внутри clipping-маски дисплея iPhone.
- Не допускать наложения системных панелей и нижней навигации.
- Устранить нежелательные тёмные полосы между экранами.
- Проверить, что движение входящего и выходящего экранов синхронизировано.
- Не допускать появления пустых областей внутри дисплея.

Не требуется заменять все переходы на crossfade.

Сохрани смысловую логику движения, но сделай промежуточные кадры аккуратнее.

---

## 03. Улучшить анимацию чека

Сейчас анимация цифрового чека стала интереснее, но при открытии всё ещё заметен промежуточный почти пустой экран.

Проблемный участок: `34.40–35.00`.

### Исправить

Чек должен появляться из предусмотренной верхней прорези.

Необходимо синхронизировать:

- Появление экрана View Receipt.
- Видимость верхней прорези.
- Появление первой части чека.
- Вертикальное движение чека.
- Появление кнопок управления.

Не оставлять заметную паузу, когда прорезь уже появилась, а сам чек ещё не виден.

### Механика

Использовать вертикальное движение цельного чека через clipping-контейнер.

Не анимировать текст и финансовые строки по отдельности.

Не добавлять новые эффекты или декоративные элементы.

Сохранить уже разработанную идею цифрового чека.

## 04. Проверить согласованность навигации

Выполнить аудит всех переходов с участием Bottom Navigation:

- Home → Card.
- Card → Activity.
- Activity → Profile.
- Другие переключения вкладок, если они используются.

### Требования

Только одна вкладка может быть активной.

Активная вкладка должна соответствовать открытому экрану.

При открытии вложенного экрана без нижней навигации Bottom Navigation должна корректно уходить вместе с предыдущим экраном.

Не допускать двойной навигации при анимации.

Если экран открывается через push transition, нижняя навигация не должна независимо оставаться поверх нового экрана.

## 05. Проверить переходные кадры интерфейса

Провести дополнительную покадровую проверку на наличие:

- Чёрных прямоугольников и кружков.
- Дублирующихся SVG-иконок.
- Неправильного z-index.
- Непредусмотренных теней.
- Мерцания текста.
- Временно исчезающих элементов.
- Неправильных активных состояний кнопок.
- Пустых областей между экранами.
- Дублированного Bottom Navigation.

Не ограничиваться просмотром по одному кадру в секунду.

Особенно важно проверять короткие промежутки в пределах 100–300 миллисекунд после нажатия.

## 06. Экспорт и качество

Текущий файл:

- 2560 × 1440.
- 60 FPS.
- HEVC.
- 10-bit.
- Продолжительность 68 секунд.

Сохранить указанные параметры, если не возникнет технической необходимости их изменить.

При этом текущий средний видеобитрейт составляет около 3.5 Мбит/с.

Для финального качественного мастера этого может быть недостаточно при большом количестве тёмных градиентов.

### Рекомендуется

- Создать высококачественный промежуточный мастер.
- Использовать 10-битный рендер с высокой точностью цветовых переходов.
- Не пережимать градиенты во время финального кодирования.
- Для финального HEVC рассмотреть более высокий битрейт или CRF-настройку с контролем качества.
- После экспорта проверить тёмные области и цветовые переходы на фактическом MP4.

Не добавлять заметный шум ради искусственного улучшения градиентов.

## 07. Что не менять

Не переделывать:

- Вступление с логотипом.
- Заголовки и описания.
- Общую композицию видео.
- Размер и положение iPhone.
- Фирменные фоновые градиенты.
- Анимацию QR-кода.
- Сцену обмена валюты.
- Режиссуру Freeze / Unfreeze.
- Экран Transaction Details.
- Музыкальное сопровождение.
- Финальную композицию.

Если для устранения ошибки потребуется небольшое изменение тайминга конкретного перехода, оно допустимо.

Не менять продолжительность всего ролика без необходимости.

## 08. Критерии приёмки V9

Результат принимается, если:

1. На всех переходах Bottom Navigation отсутствуют чёрные артефакты.
2. Иконки выбранных вкладок остаются читаемыми на протяжении всей анимации.
3. Нет двух наложенных навигационных панелей.
4. Нет непредусмотренных пустых областей при переходах.
5. Чек плавно появляется из прорези без пустой промежуточной сцены.
6. Не возникло новых ошибок в состояниях кнопок.
7. Все остальные утверждённые сцены сохранились.
8. Итоговый MP4 проверен после кодирования.

Перед экспортом отдельно покажи или проверь последовательности кадров в интервалах:

- 39.20–39.50.
- 51.70–52.00.
- 57.30–57.70.

**Главный принцип: исправить исходную причину артефактов, а не скрывать их декоративными эффектами.**

Создать версию V9 с точечными исправлениями и без переработки остального видео.
